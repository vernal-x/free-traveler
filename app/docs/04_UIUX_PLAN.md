# Free Traveler — UI/UX Plan

**Document ID:** UIUX-TRAVEL-001
**기반 문서:** `01_PRD.md`, `02_SRS_BASELINE.md`, `PROJECT_SCOPE.md`, `03_UI_COVERAGE_ANALYSIS.md`, `design-reference/vendor/airbnb/DESIGN-airbnb.md`
**대상:** 디자인, 프론트엔드
**상태:** Draft for Visual Design

---

## 1. 개요

본 문서는 `03_UI_COVERAGE_ANALYSIS.md`에서 확정한 5개 디자인 Screen(SCR-001~005)에 실제 UI 레이아웃, 디자인 토큰, Section 구성, 화면 상태를 부여한다. Airbnb 디자인 시스템(`DESIGN-airbnb.md`)은 사진 중심 마켓플레이스의 레이아웃 밀도·컴포넌트 구조·반응형 전략을 참고하는 용도로만 사용하며, Rausch 컬러(`#ff385c`), Airbnb Cereal 폰트, Airbnb 워드마크·아이콘 등 상표적 요소는 그대로 가져오지 않는다. Free Traveler는 별도의 코랄 포인트 컬러와 Inter 기반 서체 스택을 사용한다.

`PROJECT_SCOPE.md`에서 EXCLUDED로 분류된 기능(전체 콘텐츠 CMS, 미디어 업로드 워크플로, 범용 감사 로그, Moderator 개별 제재, 통합검색, URL 공유, 분석 대시보드 등)은 본 문서에서도 화면에 배치하지 않는다. 핵심 디자인 Screen은 SCR-001~005 5개로 고정한다.

## 2. 디자인 원칙

| 원칙 | 내용 |
|---|---|
| 참고와 차용의 구분 | Airbnb에서는 "사진 우선 카드, 낮은 그림자 1단계, 부드러운 라운드, 64px 섹션 리듬" 같은 **구조적 패턴**만 참고한다. 색상 값, 폰트명, 로고·마스코트, 상품명("Homes/Experiences/Services" 3-tab 구조 등)은 사용하지 않는다. |
| 신뢰 우선 | 안전정보·출처·확인일 같은 신뢰 신호는 코랄이 아닌 별도 semantic color로 구분해 마케팅 톤과 섞이지 않게 한다. |
| 밀도와 여백의 대비 | Hero·소개 섹션은 여유 있게, Card Grid는 Airbnb처럼 16~24px의 촘촘한 간격으로 배치해 정보 탐색 속도를 높인다. |
| 빈 상태도 제품 | 데이터가 없는 목록도 안내문·이용방법·CTA를 갖춘 완성된 화면으로 취급한다("빈 화면"을 만들지 않는다). |
| 5개 화면 고정 | 신규 화면을 추가하지 않고 Drawer/Modal/Tab으로 기능을 흡수한다. |

### 3.6 접근성·인터랙션 규칙

- 모든 인터랙티브 요소는 키보드 `Tab` 이동이 가능하고, 포커스 시 `color.focus-ring` 2px 아웃라인이 표시된다(코랄과 혼동되지 않는 중립색).
- 모바일 터치 대상(버튼, 아이콘 버튼, 칩, 체크박스)은 최소 44×44px을 확보한다(Airbnb의 32px 하트 버튼 같은 예외를 두지 않는다).
- 색상만으로 상태를 구분하지 않고 배지에는 항상 텍스트 라벨을 병기한다(예: 코랄 원이 아니라 "모집중" 텍스트 배지).
- 폼 오류는 `aria-describedby`로 해당 입력과 연결하고 `color.danger` 텍스트로 표시한다.

### 4.3 Section 패턴 라이브러리

같은 카드만 반복되지 않도록 아래 7개 패턴을 화면별로 교차 사용한다.

| 패턴 | 구조 | Desktop | Mobile |
|---|---|---|---|
| **Hero** | 제목 + 1~2문장 설명 + 검색/CTA | 뷰포트의 55~65%까지만 채워 다음 Section 상단이 살짝 보이도록 함 | 세로 스택, 검색·CTA 풀폭 |
| **Card Grid** | 카드 3~4열 | 1240px 기준 4열(안전정보는 3열), 20px 간격 | 1열, 16px 간격 |
| **좌우 분할(Split)** | 좌: 텍스트/리스트, 우: 이미지 또는 그 반대 | 50:50 또는 60:40 | 세로 스택(텍스트 → 이미지 순) |
| **Chip 목록** | 가로 pill 버튼 그룹 | 한 줄, 넘치면 다음 줄로 wrap | 가로 스크롤 1줄 |
| **3단계 안내** | 번호 원 + 제목 + 설명 카드 3개 | 가로 3열 | 세로 스택 |
| **CTA Banner** | `surface-soft` 또는 `primary-tint` 배경 풀폭 밴드 + 제목 + 버튼 | 중앙 정렬, 최대폭 800px 텍스트 | 세로 스택, 버튼 풀폭 |
| **Empty State** | 아이콘 + 제목 + 설명 + 1차 CTA + 보조 링크 | 카드 그리드 자리에 1개 카드 폭으로 표시 | 동일, 세로 중앙 정렬 |

이 외에 화면별로 **Filter Bar**, **Tab**, **Drawer/Modal**, **Toast**, **Status Badge**, **List+Detail Split** 컴포넌트를 사용하며 각 Screen 절에서 정의한다.

## 5. 레이아웃 공통 규칙

- 모든 화면은 `Header → Section 1..N → Footer` 순서로만 구성하며 Header/Footer 사이에 다른 전역 UI를 배치하지 않는다.
- Desktop 콘텐츠는 1200~1280px(기준 1240px) 중앙 정렬 컨테이너 안에 배치한다.
- Section 상하 여백은 Desktop 64~96px(기준 80px), Mobile 40~64px(기준 48px)로 Section마다 값을 소폭 조정할 수 있으나 범위를 벗어나지 않는다.
- Hero는 1440px 화면에서 뷰포트 전체 높이를 차지하지 않고, 스크롤 없이 다음 Section의 제목 일부가 보이도록 높이를 제한한다(권장 560~640px).
- Mobile에서 Card Grid는 항상 1열로 쌓고, 가로 스크롤 캐러셀은 Chip 목록에만 허용한다.
- 각 Section은 제목 1개, 1~3문장 설명, 실제 콘텐츠(카드/폼/타임라인 등) 또는 명확한 CTA를 반드시 포함한다. "준비 중", "정보 확인 필요", 빈 Lorem 텍스트는 사용하지 않는다.
- 데이터가 없는 목록(동행글 없음, 참가 요청 없음 등)은 Empty State 패턴으로 대체하고 안내문·이용 방법·다음 행동 CTA를 함께 제공한다.

### 6.5 SCR-005 `/account` 계정·관리

**사용자 목표:** 로그인 상태를 관리하고 내 프로필·내 활동(글·요청·차단)을 확인하며, 권한이 있으면 신고 상태와 외부 URL을 관리한다.
